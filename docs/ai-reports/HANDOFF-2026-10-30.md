### The DC model, exactly as MATPOWER computes it

This is MATPOWER's own sequence: `runpf.m` (DC branch, around lines 146–229), `makeBdc.m`,
`dcpf.m` and `bustypes.m` in `testdata/matpower/matpower8.1/lib/`. Read those files to confirm
details.

1. **Internal numbering (`ext2int`):** consecutive indices, with isolated buses (type 4) and
   out-of-service branches and generators dropped. `Case::bus_indices()` gives the label →
   position map, and the case stores labels, not indices.
2. **Bus roles (`bustypes`):**
   - REF and PV buses count as such only if they have an in-service generator; otherwise
     they're treated as PQ.
   - With no REF bus, the first PV bus becomes the reference.
3. **Branch susceptance:** `b = status / x / tap`. Use `Branch::effective_tap()`, because the
   file's tap of 0 means 1.
4. **Matrices:** `Bf = diag(b)·Cft` and `Bbus = Cftᵀ·Bf`, where `Cft` is the branch–bus
   incidence matrix (+1 at the from bus, −1 at the to bus). Parallel branches must **sum**,
   which is what `from_triplets`' COO semantics are for.
5. **Phase shifters:** `Pfinj = b·(−shift·π/180)` and `Pbusinj = Cftᵀ·Pfinj`.
6. **Net injection:** `Pbus = (in-service Pg at the bus − Pd)/baseMVA − Pbusinj − Gs/baseMVA`.
7. **Solve:** `θ[pv∪pq] = Bbus[pv∪pq, pv∪pq] \ (Pbus[pv∪pq] − Bbus[pv∪pq, ref]·θ_ref)`,
   where `θ_ref` comes from the case's `va_deg`, converted to radians.
8. **Flows:** `Pf = (Bf·θ + Pfinj)·baseMVA`, in MW. The flow at the to end is `−Pf`.
9. **Slack generation:** the **first** generator at the REF bus gets
   `Pg += (Bbus[ref,:]·θ − Pbus[ref])·baseMVA`. In case14 that turns the file's 232.4 into the
   reference's 219.0.

### Pitfalls to plan for

- **Units:** the case stores MW, MVAr and **degrees** (units are in the field names). Convert to
  per unit and radians in the DC builder, never in the case.
- **Cholesky needs B′ to be positive definite.** A negative reactance (a series capacitor) can
  make it indefinite, so catch `SparseError::NotPositiveDefinite` and fall back to `solve` (LU).
  An islanded network makes B′ singular; give that a clear error rather than a bare
  `SingularMatrix { pivot }`. Real island detection is a Phase 5 item.
- **Coverage gap:** among the committed reference cases, none has phase shifters, `Gs ≠ 0`,
  isolated buses, out-of-service elements or non-consecutive bus numbers. Only case2383wp has
  phase shifters (6), and its results must **not** be committed, for licensing reasons. So:
  - write small hand-built fixtures with hand-computed expectations for each of those paths
  - optionally, compare more cases against references generated *locally* by the harness
    (Octave is installed), without committing the output
- **Tolerances:** the reference CSVs hold MATPOWER's doubles to 17 significant digits, so a
  tolerance reflects real numerical differences (solver and summation order), not formatting.
  State it in the test.

## Conventions the maintainer expects

- **One commit per checklist item**, with descriptive messages explaining *why*. End each with
  your own model's `Co-Authored-By:` trailer, which the harness's system reminder gives.
- **Branch names** start with `dev/` (for example `dev/parser-hardening`). Never commit to
  `main`.
- **Reports:** each PR gets a report `docs/ai-reports/REPORT-<N>.md`; the next is `REPORT-9`.
  The PR description is that report followed by
  `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. Take figures such as diff
  sizes and test counts from git and the test runner, not from estimates; past estimates were
  wrong twice. One technique: commit with a placeholder, read `git diff --shortstat`,
  substitute it, and amend before pushing.
- **The maintainer reviews and merges PRs.** Push and open PRs when asked. They often ask for
  stacked PRs when work depends on unmerged work.
- **Documentation style:**
  - doc comments on every public item, stating semantics on the signature (duplicate handling,
    zero handling, panics versus `Result`)
  - units in field names
  - matching the surrounding code's density
- **Errors** are `Result`s with specific variants (`SparseError`, `PowerflowError`, both
  `#[non_exhaustive]`). Panics are only for operators and documented impossible cases.
- **Verify before claiming.** The maintainer values evidence: probes, surveys over real data,
  fuzz tests written before fixes, and logs checked after CI rather than just its status.
  Report mistakes openly in the report's "Mistakes caught" section.

## Checks to run

- **`./check.sh`:** fmt, clippy with `-D warnings` (all features and each feature alone), tests
  (no features, all features, each feature alone) and doc tests. Run it with
  `YBUS_REQUIRE_CASES=1` so the MATPOWER-dependent tests fail instead of skipping.
- **MSRV:** `cargo +1.87 test --workspace --all-targets --all-features`. Toolchains 1.86 and
  1.87 are installed; `rust-version` in the root `Cargo.toml` is 1.87, and the resolver is
  MSRV-aware.
- **Docs:** `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --workspace --all-features`. A
  public doc linking to a private item fails it.
- **Dependencies:** `cargo deny --all-features check` runs in CI; `cargo-deny` isn't installed
  locally. Its license allow list is MIT, Apache-2.0 and Unicode-3.0, so a crate pulling in
  `Apache-2.0 WITH LLVM-exception` (for example `tempfile`, through `rustix`) would fail it. For
  scratch directories, tests use `CARGO_TARGET_TMPDIR` instead.

## Pitfalls already hit (don't repeat them)

- **Stacked branches:** after amending a commit on the lower branch, rebase the upper one with
  `git rebase --onto <lower> <old-commit> <upper>`. A plain rebase replays the old commit and
  conflicts.
- **Retargeted PRs:** GitHub may rewrite commits when it retargets a stacked PR, so a merged
  local branch might not be an ancestor of `main`. Before deleting it, check
  `git diff --quiet <branch> main`.
- **Stale tracking refs:** after deleting a remote branch, run `git fetch --prune`.
- **Clippy's `upper_case_acronyms`** only fires on *private* items by default, since renaming
  public ones would break the API. A scratch test with a `pub` item will wrongly pass.
- **MATPOWER's `savecase` writes `%.9g`** and loses precision. Use `%.17g`, as the scripts do.
- **MATPOWER v2 rows can lack optional columns:** case533mt has 18-column generator rows.
  Missing ones default as MATPOWER's `mpc_1to2` does.

## Known issues and follow-ups (not urgent)

- **Wasted capacity in `Case`:** about 28–39% unused `Vec` capacity (34.0 MB for the
  82,000-bus `case_SyntheticUSA`, of which about 20.6 MB is data). The tables are collected
  through `Result`, which can't pre-size; pre-allocate or `shrink_to_fit`. The parse peak is
  about 3× the result.
- **CI time:** the Check job takes about 2.5 minutes, because `check.sh` runs the suite four
  times and the MATPOWER-wide tests take about 15 s per pass in debug builds.
- **Version 1 case files** are rejected clearly; converting them, as `mpc_1to2` does, is a
  possible follow-up.
- **Octave versions:** the reference CSVs were generated with Octave 6.4 in another
  environment, and CI and this machine use 8.4. It shouldn't matter, and `VERSIONS` and `SOURCE`
  record the versions.
- **`write_matrix_market`** panics for dimensions near `usize::MAX`. That's documented and low
  priority.
- **After Phase 1.5:** Phase 2 (a fixed-pattern `CsrMatrix` with assembly maps), Phase 3 (a
  Gilbert–Peierls LU with orderings and refactorization) and later phases are in the checklist.
